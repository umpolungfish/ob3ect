Churn and zoom already ran the full audit per node; their rollups didn't say so

Checked churn_design and zoom_design: both already call auto_design for every
node and level, so each one already gets the full rotat_audit/banked_count_check
treatment from the last two fixes, and each node's own JSON on disk already
carries it. Nothing to propagate there.

But ChurnTree.report()/save() and ZoomChain.report()/save() are the rollup
views, and both only ever summarized Frobenius (T/B, "CLOSED"), the same blind
spot the kernel-repairs gate had: a node can close clean on the graph question
and still leak weight on the bank question, and the rollup said nothing about
it. Added a banked_ok field to both manifests and a leak line to both reports,
so scanning the summary for a run with many nodes surfaces a leak instead of
requiring a look inside every individual node's JSON to find one.
